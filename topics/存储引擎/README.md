# 主题：存储引擎的物理学 —— 持久化是在和硬件的谎言作斗争

一条脊梁：**"写进数据库了"是一句要拆开好几层的话。** 应用 buffer → 内核 page cache → 磁盘控制器 cache → 盘片，每一层都可能在你以为"落盘"时，只是把数据攥在手里、随时准备断电就扔。持久化工程的全部，就是和这些"善意的谎言"以及无处不在的重排序作斗争——而这件事，和[并发原理](../并发原理/)里的内存可见性，是同一道数学题：没有显式的屏障，下层就有权不让你的写"对所有人、对未来的崩溃"可见。

本主题用十问，把"数据是怎么安全地、快速地躺到盘上、又被高效地找回来"讲到见底。Go 后端日常打交道的 MySQL/PostgreSQL/Redis/RocksDB，全在这十问的射程内。

> 顺序读 [深讲十问](./深讲十问.md)。

## 十问索引
1. `write()` 成功 = 落盘了吗？连 fsync 也撒谎
2. WAL：为什么写两次反而更安全、更快
3. B+ 树为什么"矮胖"——它在迁就谁
4. LSM 凭什么挑战 B+ 树，compaction 为什么是双刃
5. 隔离级别，和内存模型的乱序自由为什么同构
6. MVCC 为什么读写不互锁，长事务为什么是诅咒
7. 索引为什么在写密集是负优化，最左前缀是物理推论
8. 删除为什么是写墓碑，删完为什么更慢
9. 信任 OS page cache vs 自建 buffer pool，O_DIRECT 为什么存在
10. SSD 没磁头了，顺序写为什么还更快
