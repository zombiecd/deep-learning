# 主题：性能工程 —— 你以为的瓶颈几乎总是错的

一条脊梁：**人的直觉对"瓶颈在哪"几乎总是错的，所以方法（测量、建模、定位）凌驾于技巧之上。** 优化没测量过的地方，等于在黑暗里装修。这条脊梁是[元认知](../../)"感觉良好≠做对了"的硬核版——验证靠数据，不靠"我觉得"。

本主题用十问，把"怎么科学地让系统更快、以及更重要的——怎么知道该不该优化、优化到哪儿停"讲到见底。Amdahl、排队论、利特尔法则、尾延迟、火焰图——性能工程的科学方法全在射程内。延续作者并发 bench 的经验。

> 顺序读 [深讲十问](./深讲十问.md)。第 2 问连[并发原理](../并发原理/)"核越多越慢"；第 5 问连[可观测性](../可观测性/)协调遗漏；第 7 问连[编译器与运行时](../编译器与运行时/)内存布局；第 10 问连[可靠性工程](../可靠性工程/) SLO。
